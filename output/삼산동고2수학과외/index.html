삼산동 고2수학과외 로그 계산에서 밑과 진수를 혼동하지 않는 방법 페이지입니다. 현재 학습 상태를 점검하고 시험 준비 순서를 세우는 방법을 안내합니다.

로그 계산에서 먼저 구분해야 할 두 자리

로그 문제를 풀 때 계산 과정은 맞는 것 같은데 답이 계속 달라지는 학생들이 있습니다. 식을 변형하는 방법을 몰라서가 아니라, 로그의 밑과 진수를 서로 바꾸어 읽는 데서 오류가 시작되는 경우가 많습니다. logab에서 아래쪽에 작게 표시된 a는 밑이고, 뒤에 놓인 b는 진수입니다. 이 두 수의 역할은 같지 않으므로 위치만 보고 외우기보다 각각 어떤 질문에 답하는지 이해해야 합니다.

밑은 “몇을 거듭제곱하는가”, 진수는 “그 결과가 무엇인가”를 나타냅니다.

logab를 하나의 질문으로 읽기

로그의 정의는 logab = x일 때 ax = b라는 뜻입니다. 따라서 밑 a는 거듭제곱의 기준이 되고, 진수 b는 거듭제곱한 결과가 됩니다. 예를 들어 log28 = 3은 “2를 몇 제곱해야 8이 되는가?”라는 질문입니다. 여기서 2를 8로 바꾸면 log82가 되어 전혀 다른 값이 됩니다. 8을 몇 제곱해야 2가 되는지를 묻는 식이기 때문입니다.

계산 전에 식을 소리 내어 읽어보는 것도 효과적입니다. log381은 “3을 몇 제곱해서 81이 되는가?”라고 읽고, log813은 “81을 몇 제곱해서 3이 되는가?”라고 읽습니다. 두 식을 나란히 적어 보면 밑과 진수의 위치를 바꾸는 것이 단순한 순서 변경이 아니라 문제 자체를 바꾸는 일임을 확인할 수 있습니다.

밑과 진수의 위치를 표시하는 습관

삼산동고2수학과외에서 로그 계산을 지도할 때도 처음부터 공식을 적용하기보다 식의 역할을 표시하게 하는 것이 중요합니다. 문제를 보자마자 숫자에 동그라미를 치는 대신, 밑에는 ‘기준’, 진수에는 ‘결과’라고 짧게 적어보세요. log5125라면 5 아래에 기준, 125 옆에 결과를 적은 뒤 5x = 125로 바꿉니다. 그러면 x=3이라는 답을 구하는 과정이 자연스럽게 이어집니다.

특히 괄호가 포함된 식에서는 진수의 범위를 먼저 확인해야 합니다. log2(x-1)에서 진수는 x가 아니라 x-1 전체입니다. 따라서 로그의 정의가 성립하려면 x-1>0, 즉 x>1이어야 합니다. log2x-1처럼 괄호가 없는 표현은 log2x에서 1을 뺀 것인지, 진수가 x-1인 것인지 문맥에 따라 다르게 해석될 수 있으므로 식을 정확히 확인해야 합니다.

자주 나오는 혼동 유형

첫 번째 오류는 밑을 지수처럼 생각하는 것입니다. log216에서 2는 답을 구할 때 지수로 등장하지만, 처음부터 지수인 것은 아닙니다. 2x=16이라는 식을 만든 뒤 x를 찾는 과정에서 지수의 위치에 놓입니다. 밑과 지수의 역할을 구분하지 않으면 log216을 216처럼 잘못 계산할 수 있습니다.

두 번째 오류는 진수를 밑으로 옮겨 적는 것입니다. log464를 464로 바꾸는 식입니다. 로그식에서 진수는 거듭제곱의 결과이므로 4x=64로 바꾸어야 합니다. 변환 후에도 원래 식의 밑이 그대로 거듭제곱의 밑으로 남아 있는지 확인하면 이 실수를 줄일 수 있습니다.

세 번째 오류는 밑이 같을 때만 로그의 진수를 비교해야 한다는 사실을 놓치는 것입니다. log28과 log48은 진수는 같지만 밑이 다르므로 같은 값이 아닙니다. 반대로 log28과 log216은 밑이 같기 때문에 각각 3과 4로 비교할 수 있습니다. 로그끼리 크기를 비교하거나 계산할 때는 먼저 밑이 같은지 살펴보는 습관이 필요합니다.

계산 공식에서 역할을 확인하는 방법

로그의 곱셈 법칙을 사용할 때도 밑과 진수를 따로 확인해야 합니다. 밑이 같은 경우 logaM + logaN = loga(MN)입니다. 두 로그의 밑이 a로 같고, 진수 M과 N이 곱해지는 구조입니다. 예를 들어 log35 + log37은 log335가 됩니다. 밑까지 곱하는 것이 아니며, 진수만 결합합니다.

마찬가지로 logaM - logaN = loga(M/N)에서도 밑은 그대로이고 진수끼리 나누어집니다. 학생이 밑과 진수를 혼동하면 log35 + log37을 log635처럼 처리하기도 합니다. 공식을 외우기 전에 “같은 밑을 유지하고 진수끼리 계산한다”는 구조를 식에 표시해보세요.

밑변환 공식에서 생기는 착각

밑변환 공식은 logab = logcb / logca입니다. 여기서 원래 로그의 진수 b는 분자의 진수가 되고, 원래 로그의 밑 a는 분모의 진수가 됩니다. 두 값의 위치가 서로 바뀐 것처럼 보여 혼동하기 쉽지만, 원래 식의 밑이 분모 쪽에 온다는 점이 핵심입니다.

예를 들어 log27을 상용로그로 바꾸면 log 7 / log 2입니다. log 2 / log 7이 아니므로, 변환한 뒤에는 원래 식에서 밑과 진수가 어디였는지 다시 대조해야 합니다. 계산기를 사용하더라도 먼저 손으로 분자와 분모를 정한 뒤 입력하는 편이 안전합니다.

문제를 풀 때의 짧은 점검 순서

  • 로그 기호 아래의 수를 밑으로 표시한다.
  • 괄호를 포함해 진수의 범위를 확인한다.
  • logab를 보면 ax=b로 바꾸어 본다.
  • 공식을 적용할 때 밑은 유지되는지, 진수끼리 계산되는지 확인한다.
  • 계산 결과를 다시 거듭제곱으로 바꾸어 원래 진수가 나오는지 검산한다.

이 과정을 모든 문제에 길게 적을 필요는 없습니다. 처음에는 식 옆에 ‘밑’과 ‘진수’를 써서 위치를 익히고, 익숙해진 뒤에는 눈으로 확인하는 정도로 줄이면 됩니다. 다만 오답이 발생했을 때는 답만 고치지 말고, 밑을 잘못 읽었는지, 진수의 범위를 잘못 잡았는지, 공식 적용 중 위치를 바꾸었는지를 구분해야 같은 실수가 반복되지 않습니다.

삼산동고2수학과외 학습에서도 로그 계산의 속도보다 처음 식을 정확히 읽는 습관을 우선하면 복잡한 변형 문제에서 흔들리는 일이 줄어듭니다. 로그를 볼 때마다 “무엇을 몇 제곱해서 무엇을 만드는가?”라고 질문하면 밑과 진수의 역할이 분명해지고, 계산 공식도 위치를 바꾸지 않고 사용할 수 있습니다. 이런 읽기 습관이 자리 잡은 뒤에야 계산 연습의 효과도 제대로 나타납니다.

결국 로그 계산의 출발점은 공식 암기가 아니라 식의 구조를 보존하는 것입니다. 삼산동고2수학과외에서 문제를 풀 때도 답을 빨리 구하려 하기보다 밑을 기준으로, 진수를 결과로 해석한 다음 식을 변환해보세요. 작은 위치 차이를 정확히 구분하는 것이 로그 문제의 기본 계산을 안정적으로 만드는 방법입니다.
